## Workflows Break.Your AI Can Fix Them.

n8n-mcp doesn't ship an agent — it's the connector that gives the AI you already use the hands for production work: honest validation, testing, real execution logs, surgical edits, and version history with rollback. Where the Public API stops, n8n-mcp talks to n8n's native MCP server: pinned-data test runs, native version history, live dropdowns, n8n Agents. The intelligence is yours; the tools are ours.

A workflow failed overnight

InspectAI reads the execution log

DiagnoseRoot cause, not guesswork

PatchOne surgical diff edit

VerifyRe-run passes — minutes, not hours

Bad fix? Roll back to any n8n version, or our snapshot, in one call.

An agent loop is only as good as its stop signal. n8n-mcp fails loudly on unknown nodes, invalid versions, and missing required fields — so when your AI says"valid", it means it.

## Already Using n8n's Built-In MCP?Keep It.

n8n ships its own MCP server, and it covers a lot. n8n-mcp is built to sit on top of it, not to replace it. Here is how to tell which you need.

### The built-in server is enough when

* You work with a single n8n instance
* That instance runs a recent n8n 2.x
* You build and edit workflows on that one instance
* You set up credentials yourself in the n8n UI

### Add n8n-mcp when

* You run more than one instance — prod and staging, or your clients'
* Your AI should create and update credentials, not only list them
* You're on an older n8n — 1.x or early 2.x — that predates most built-in MCP tools
* You want validation that fails loudly, autofix, execution error analysis, and a security audit

### Or use both through one connection

Add your instance-level MCP token next to your API key and n8n-mcp routes the native-only features through n8n's own server: test runs for any trigger with pinned data, n8n's version history with diff and rollback, live dropdown values, and n8n Agents. Your AI still sees one MCP server.
